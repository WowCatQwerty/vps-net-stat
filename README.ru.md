# vps-net-stat

[English](README.md) | **Русский**

Простой монитор трафика и портов для Linux-серверов.  
Считает входящий/исходящий трафик по дням и месяцам, отслеживает открытые порты с именами процессов, точно считает трафик по портам через iptables/nftables. Данные хранятся в SQLite и **переживают перезагрузки**.

## Установка

```bash
curl -fsSL https://raw.githubusercontent.com/WowCatQwerty/vps-net-stat/main/install.sh | sudo bash
```

> ⚠️ Требуются права root.

## Отслеживание трафика по портам

По умолчанию трафик по портам **не собирается** — добавляй только те что интересны.

<details>
<summary>Показать детали: как добавить порт, backend файрвола, частота сканирования, часовой пояс</summary>

**Как добавить порт:**

1. Открой `vns`
2. Выбери `[2]` — посмотри какие порты заняты и чем
3. Выбери `[7]` — введи номер порта, протокол, необязательный комментарий
4. Трафик начнёт копиться с этого момента

```text
  Номер порта (например 80): 443
  Протокол: [1] tcp  [2] udp  [3] оба
  → 1
  Комментарий (необязательно): nginx HTTPS
  ✓ Порт добавлен в отслеживание.
```

Трафик по портам измеряется через **iptables/nftables** — точно, без пропусков.  
Файрвол определяется автоматически (приоритет nftables, fallback на iptables).  
Создаётся отдельная цепочка `VNS_TRACK` — существующие правила не затрагиваются.  
Правила автоматически очищаются при остановке сервиса или удалении программы.

**Нет файрвола?** Если не найдены ни `iptables`, ни `nftables`, vps-net-stat автоматически
переключается на отслеживание через `ss`. Это менее точный режим:
- Только TCP — UDP-порты в этом режиме не отслеживаются (у `ss` нет байтовых счётчиков для UDP).
- Очень короткие соединения, полностью завершившиеся между двумя опросами, могут быть недосчитаны.

Активный backend отображается в `vns` → `[14] Информация о системе`. В режиме `ss` предупреждение также показывается сразу при добавлении порта в отслеживание и повторно в системной информации — точность в этом режиме не гарантируется.

**Частота проверки по умолчанию:**
- Общий трафик сервера — каждые **60 секунд**
- Трафик по портам — каждые **30 секунд**
- Сканирование портов — каждые **300 секунд** (5 минут)

Изменить: переменные `INTERVAL` и `PORT_INTERVAL` в начале `/opt/vps-net-stat/vps-net-stat.py`.

**Часовой пояс:** день в статистике меняется в полночь по **времени сервера**. Проверить или изменить:
```bash
timedatectl status                      # текущий часовой пояс
timedatectl set-timezone Europe/Moscow  # установить часовой пояс
```

## Экспорт / Импорт

Через меню: `vns` → `[12]`

**Экспорт** сохраняет данные в директорию (по умолчанию `/root/vns-backup`) в CSV, JSON или в оба формата.

**Импорт** читает бэкап из указанной директории. Сначала ищет `vns_export.json`; если его нет —
переключается на чтение CSV-файлов (`vns_traffic.csv`, `vns_port_traffic.csv`, `vns_watched.csv`) —
что найдёт, то и загрузит. Перед импортом показывает, что именно найдено в бэкапе.

Если запись из бэкапа уже существует (совпадает день/порт/протокол), программа спрашивает как поступить:
- **Суммировать трафик** — прибавить значения из бэкапа к текущим
- **Оставить текущие данные** — пропустить значение из бэкапа, текущие данные не трогаются
- **Заменить данными из бэкапа** — перезаписать текущие значения данными из бэкапа

## Безопасность

При установке и обновлении автоматически проверяется SHA-256 контрольная сумма каждого файла.  
Хэши хранятся в `checksums.txt` и прикладываются к каждому релизу в разделе Assets.

Проверить вручную:
```bash
sha256sum /opt/vps-net-stat/vps-net-stat.py
sha256sum /opt/vps-net-stat/vns.py
```
Сравни с `checksums.txt` из Assets нужного релиза на GitHub.

## Как это работает

| Компонент | Описание |
|---|---|
| `vps-net-stat.py` | Демон — читает `/proc/net/dev` для общего трафика, использует iptables/nftables для трафика по портам |
| `vns.py` | CLI с интерактивным меню |
| `vps-net-stat.service` | systemd-юнит, автозапуск после перезагрузки |
| `/var/lib/vps-net-stat/data.db` | SQLite-база, данные копятся бесконечно |
| `/var/log/vps-net-stat/daemon.log` | Лог демона |
| `/etc/vps-net-stat/lang` | Выбранный язык интерфейса |
| `/etc/vps-net-stat/firewall` | Определённый backend трафика по портам (iptables/nftables/ss) |

**Интерфейсы определяются автоматически** через `ip route`. Виртуальные интерфейсы (docker, veth, tun, lo и т.д.) исключаются.

## Сравнение с аналогами

> **Примечание:** все инструменты поддерживают IPv6 и мониторинг нескольких интерфейсов. Чисто real-time инструменты (nload, iftop, bmon) исключены — они не хранят историю.

| Функция | vps-net-stat | darkstat | vnStat | ntopng | netdata |
|---|:---:|:---:|:---:|:---:|:---:|
| **Точный трафик по портам** | ✅ (iptables/nftables) | 🟡 (по хостам, не точные байты) | ❌ | ✅ (DPI + потоки) | 🟡 (через eBPF, приближённо) |
| **Имена процессов** | ✅ (порт → процесс) | ❌ | ❌ | 🟡 (с nProbe+sysdig) | ✅ (apps.plugin) |
| **Веб-интерфейс** | 🟡 (в планах) | ✅ | 🟡 (только статичные картинки vnstati) | ✅ | ✅ |
| **Встроенные алерты** | 🟡 (в планах) | ❌ | ❌ | ✅ | ✅ |
| **CLI-интерфейс** | ✅ TUI-меню | ❌ (только веб) | ✅ Команды | 🟡 (веб основной) | 🟡 (веб основной) |
| **DPI / определение протоколов** | ❌ | 🟡 (базовое) | ❌ | ✅ (nDPI) | 🟡 (частично) |
| **Данные переживают перезагрузку** | ✅ (SQLite, по умолчанию) | 🟡 (нужна настройка --export/--import) | ✅ (бинарная БД, по умолчанию) | ✅ | ✅ |
| **Экспорт данных** | ✅ CSV/JSON | ❌ | 🟡 JSON/XML | ✅ REST API | ✅ API / Prometheus |
| **Потребление ресурсов** | 🟢 Низкое | 🟢 Низкое | 🟢 Низкое | 🔴 Высокое | 🔴 Высокое |
| **Простота установки** | 🟢 Просто | 🟢 Просто | 🟢 Просто | 🔴 Сложно | 🟡 Средне |
| **Работа без настройки** | 🟢 Да | 🟡 (нужен export/import для сохранности) | 🟢 Да | 🔴 Нет | 🟢 Да |

**Обозначения:** ✅ Да / ❌ Нет / 🟡 Частично или требует настройки / 🟢🔴🟡 Оценка

<details>
<summary><strong>Пояснения по отдельным пунктам</strong> (нажми, чтобы раскрыть)</summary>

| Функция | Пояснение |
|---|---|
| **Точный трафик по портам** | Точные байтовые счётчики через правила файрвола (iptables/nftables). darkstat использует перехват пакетов через libpcap — видит хосты и порты, но не считает точные байты по каждому порту. netdata использует трассировку через eBPF — приближённо, не точные счётчики. vnStat вообще не отслеживает порты. |
| **Имена процессов** | vps-net-stat сопоставляет открытые порты с процессами через `ss`. У netdata встроен `apps.plugin` для мониторинга процессов. ntopng требует nProbe (часть функций платная) + модуль ядра sysdig — из коробки недоступно. darkstat и vnStat не показывают имена процессов. |
| **Веб-интерфейс** | У darkstat и ntopng полноценные веб-интерфейсы. netdata изначально веб-ориентирован. vnStat генерирует статичные картинки через `vnstati`. vps-net-stat — только CLI/TUI, веб-интерфейс в планах. |
| **Встроенные алерты** | Встроенные системы уведомлений. У ntopng и netdata настраиваемые алерты. vps-net-stat планирует интеграцию с Telegram. У darkstat и vnStat алертов нет. |
| **CLI-интерфейс** | У vps-net-stat интерактивное TUI-меню. vnStat работает через команды в терминале. У darkstat нет CLI вообще (только веб). ntopng и netdata в основном веб-ориентированы, CLI ограничен. |
| **DPI / определение протоколов** | Глубокий анализ пакетов (Deep Packet Inspection) — разбор содержимого пакетов для определения протокола (YouTube, SSH и т.д.). ntopng использует библиотеку nDPI. У darkstat базовое определение протоколов. У netdata частичная поддержка. У vps-net-stat и vnStat DPI нет. |
| **Данные переживают перезагрузку** | Постоянное хранилище по умолчанию. vps-net-stat использует SQLite. vnStat — бинарную базу. ntopng и netdata хранят данные постоянно. darkstat по умолчанию хранит данные в памяти; для сохранности нужна ручная настройка `--export`/`--import`. |
| **Экспорт данных** | vps-net-stat экспортирует в CSV и JSON. У ntopng и netdata есть REST API. У vnStat есть вывод в JSON/XML, но нет полного экспорта истории. У darkstat экспорта нет вообще. |
| **Потребление ресурсов** | Приблизительная классификация. vps-net-stat, darkstat и vnStat — лёгкие демоны. ntopng требователен к ресурсам (нужно заметное количество RAM/CPU). Потребление памяти у netdata растёт напрямую от количества собираемых метрик — чем больше подключено плагинов и источников данных, тем больше RAM он потребляет со временем; есть подтверждённые случаи, когда потребление памяти на долго работающих инстансах значительно превышало ожидаемое по умолчанию, а в контейнерных окружениях это приводило к перезапускам из-за нехватки памяти. |
| **Простота установки** | У vps-net-stat, darkstat и vnStat установка одной командой или через пакетный менеджер. ntopng требует сложной настройки. netdata — средне: установка простая, но много опций для настройки. |
| **Работа без настройки** | Работает сразу после установки без ручной конфигурации. vps-net-stat, vnStat и netdata работают из коробки. darkstat требует настройки export/import для сохранности данных. ntopng нужна настройка. |

</details>
